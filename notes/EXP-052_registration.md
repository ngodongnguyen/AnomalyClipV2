### EXP-052 — Source-only operating points for the extent axis (H041; no training, no medical label used for any choice)

- **Hypothesis / status:** H041 / PLANNED (drafted 2026-10-15 before any EXP-052 code ran on real data; the user must confirm the rule and the paper decision below before the first run; do not change either after seeing numbers).
- **Why:** every ECP result so far uses `z_img = -0.69`, `z_pix = 1.6`, values historically chosen while looking at the medical development sets (D027: no independent confirmation set exists). A reviewer will ask how the operating point is chosen without target data. EXP-020 also showed that the same values do not transfer to a VisA-trained ECP: its image AUROC fell 8.9 / 20.6 / 24.0 points below the VisA-trained no-zoom control (HeadCT / BrainMRI / Br35H).
- **H041:** a rule that uses only source-side information reproduces the medical behaviour of the deployed operating point for MVTec-trained ECP (ECP still beats zoom-only under the EXP-024 rules), and repairs the VisA-trained image head.
- **The rule (fixed now; one rule per head, chosen before any number):**
  - **z_pix = P95 of the training-mixture extent labels** of the source: the z values the conditioner saw during training (native frames and zoom crops of the source anomalies), simulated with the exact training crop code (`_sample_crop_box` compiled from `dataset.py`, uniform placement, zoom p 0.5, target 0.10-0.45, seed 111, 15 epochs, image outer / epoch inner as EXP-040; MVTec must reproduce the EXP-040 counts 9,407 / 8,768, else STOP). No model, no target data. Rationale fixed now: the pixel head is read at the large end of the learned extent axis because the paper's targets are medical lesions (scope decision, CLAUDE.md); P95 rather than the maximum to avoid a single outlier.
  - **z_img = the z of the grid {-0.69, -0.3, 0.0, 0.4, 0.8, 1.2, 1.6} with the highest macro (per-category mean) image AUROC on the other industrial dataset of the AnomalyCLIP protocol:** VisA for MVTec-trained checkpoints, MVTec for the VisA-trained one; ties (equal after rounding to 1e-9) go to the smaller z; each checkpoint gets its own scan. No medical data. Rationale: image-level anomaly presence is a task the industrial datasets share; the pixel head is not chosen this way because industrial defects are much smaller than medical lesions (VisA prefers small z_pix, CLAUDE.md scope note).
  - Scores are exactly test.py's image score (softmax(image features . text(z) / 0.07)[anomalous]); the text features at a fixed z do not depend on the image in ECP 'extent' mode, which the scan checks on two images (STOP if they differ by > 1e-5). **Parity gate:** on HeadCT, the scan's scores at z -0.69 must equal test.py's exported image scores within 1e-4 (STOP otherwise).
- **Checkpoints:** matched ECP seeds 111 (`checkpoints/EXP-012-matched/ecp_extent/checkpoints`), 222, 333 (`checkpoints/matched_ecp_s{222,333}`), MVTec-trained; `checkpoints/ecp_visa` (EXP-020, VisA-trained, seed 111). Zoom-only (ZO) seeds 111/222/333 and the VisA-trained references (`ecp_visa`, `zoom_visa`, `ctrl_visa` at -0.69 / 1.6, EXP-020) are existing numbers; z does not apply to ZO / controls.
- **Evaluation:** `run_ecp.sh fixed_ckpt <ckpt> <z_img rule> <z_pix rule> "" _srcz` (unchanged test.py, sigma 4, `--features_list 24`): pooled pixel AUROC / AUPRO on ClinicDB, Kvasir, ColonDB, ISIC, Endo, TN3K; image AUROC / AP on HeadCT, BrainMRI, Br35H.
- **PRE-REGISTERED RULES:**
  - **R1 (MVTec-trained, 3 seeds; does ECP still beat zoom-only when the operating point is source-only?):** EXP-024 R1 applied to ECP-at-rule versus ZO: a WIN is a seed-mean difference >= +1.0 point that is positive in all three seeds; CONFIRMED if PRO wins on >= 4/6 AND AUROC wins on >= 4/6 pixel sets; NOT CONFIRMED if wins on <= 2/6 for either; otherwise INCONCLUSIVE.
  - **R3 (image head, same seeds):** ECP-at-rule versus ZO image AUROC wins (same definition) on >= 2/3 image sets -> CONFIRMED, otherwise NOT CONFIRMED.
  - **R2 (cost of the source rule, descriptive):** seed-mean (rule - deployed) per set; COSTS if any pixel AUROC or PRO, or any image AUROC, changes by <= -1.0 point; otherwise COMPARABLE (gains allowed, reported).
  - **VisA image head (one seed):** RECOVERED if ecp_visa at its rule has image AUROC >= ctrl_visa - 1.0 on >= 2/3 image sets, otherwise NOT RECOVERED. Report-only: ecp_visa at the rule minus zoom_visa on the six pixel sets.
- **Paper decision proposed with this registration (to be confirmed by the user before the run, recorded in DECISIONS.md):** from EXP-052 on, the headline ECP numbers in the paper are the ones at the source-only rule, whatever R1 / R2 / R3 return; the deployed (-0.69 / 1.6) numbers are reported as the historical development-set operating point and labelled as such.
- **Reading limits (written before the run):** the grid for z_img, the percentile for z_pix and the rationale of reading the pixel head at the large end are fixed by us, not learned, and the large-end choice encodes the medical scope (a domain prior, not a target label); the MVTec scan for the VisA-trained model uses MVTec test images that are disjoint from its training data, the VisA scan for MVTec-trained models likewise; one VisA-trained seed; development sets (D027); the deployed values were themselves chosen on these medical sets, so R2 compares against an optimistic reference.
- **Cost (estimate, unmeasured):** quantiles CPU, a few minutes; parity about 5 min; scans about 10 min per checkpoint (one encoder forward per image, 7 text encodings in total); evaluation about 85 min per checkpoint (four checkpoints, about 6 h, sequential).
- **Code:** `zsel_stats.py`, `test_zsel_stats.py` (quantile rule, exact AUROC, macro AUROC, z selection with ties, R1 / R2 / R3 / VisA rules at their boundaries), `analyze_zsel.py` (`quantiles`, `imgscan` with the image-independence guard and the test.py parity option, `rule`, `report`), `scripts/run_exp052.sh` (`check`, `quantiles`, `parity`, `imgscan`, `eval`, `report`). Local checks: unit tests pass on CPU; quantiles and report ran end to end on a synthetic tree. Not tested locally: real data, GPU scan, test.py parity.
